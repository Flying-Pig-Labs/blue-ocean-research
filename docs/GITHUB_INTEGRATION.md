# GitHub Integration Documentation

## Overview

The GitHub integration module (`github_integration.py`) provides automated repository creation and issue management for the product ideas generated by the multi-step LLM pipeline. This feature transforms analysis outputs into an actionable GitHub project with comprehensive documentation and trackable issues.

## Features

### 🚀 Automatic Repository Creation
- Creates new GitHub repositories (public or private)
- Handles existing repositories gracefully
- Configurable repository naming

### 📝 Comprehensive README Generation
The README includes:
- **Executive Summary**: Market opportunity overview
- **JTBD Analysis**: Top jobs with opportunity scores
- **Opportunity Zones**: Weighted zones with market sizes
- **Product Portfolio**: All ideas with links to issues
- **Consolidation Opportunities**: Strategic product combinations
- **Implementation Roadmap**: Phased approach
- **Financial Projections**: Development costs and revenue estimates

### 🎯 Smart Issue Creation
Each product idea becomes a GitHub issue with:
- **Product Overview**: Description and value proposition
- **Target Jobs**: Mapped JTBD with opportunity scores
- **Key Features**: Detailed feature list
- **Market Analysis**: Target market and sizing
- **Feasibility Scores**: Technical, market, resource, and risk ratings
- **Business Case**: Time, cost, and revenue model
- **Implementation Priority**: Based on impact/effort matrix

### 🏷️ Intelligent Labeling System
Automatic labels include:
- **Priority**: `high-priority`, `medium-priority`, `low-priority`
- **Category**: `ai-powered`, `mobile`, `integration`, `analytics`, `security`
- **Phase**: `phase-1`, `phase-2`, `phase-3`, `phase-4`
- **Special**: `quick-win`, `needs-validation`, `product-idea`

## Usage

### Command Line Interface

```bash
# Basic usage - create public repository
python product_idea_generator.py --github

# Custom repository name
python product_idea_generator.py --github --repo-name "my-innovations-2024"

# Create private repository
python product_idea_generator.py --github --repo-name "confidential-ideas" --github-private

# Full pipeline with all options
python product_idea_generator.py \
  --input value_curves.json \
  --json-output ideas.json \
  --report-output ideas.md \
  --github \
  --repo-name "market-analysis-q4" \
  --github-private
```

### Programmatic Usage

```python
from github_integration import create_github_output

# Load your analysis data
research_analysis = {...}  # From research_analyzer.py
jtbd_data = {...}          # From jobs_researcher.py
zones_data = {...}         # From cluster_jtbd.py
ideas_data = {...}         # From product_idea_generator.py

# Create GitHub repository
result = create_github_output(
    research_analysis=research_analysis,
    jtbd_data=jtbd_data,
    zones_data=zones_data,
    ideas_data=ideas_data,
    repo_name="innovation-portfolio-2024",
    github_token="your_token",  # Optional if set in environment
    create_issues=True,
    private=False
)

if result['success']:
    print(f"Repository created: {result['repo_url']}")
    print(f"Issues created: {result['issues_created']}")
```

## Configuration

### Environment Variables

```bash
# Required for GitHub integration
export GITHUB_TOKEN=ghp_your_personal_access_token

# Optional: Set default repository settings
export GITHUB_DEFAULT_PRIVATE=true
export GITHUB_DEFAULT_REPO_PREFIX=innovation-
```

### Token Permissions

Required GitHub token scopes:
- `repo` - Full control of private repositories (if creating private repos)
- `public_repo` - Access to create public repositories

## Error Handling

The integration includes comprehensive error handling:

| Error | Cause | Solution |
|-------|-------|----------|
| `Bad credentials` | Invalid token | Verify token and regenerate if needed |
| `Repository already exists` | Duplicate name | Uses existing repo or choose different name |
| `Rate limit exceeded` | Too many API calls | Wait for reset or use different token |
| `Resource not accessible` | Insufficient permissions | Check token scopes |

## Best Practices

### 1. Repository Naming
- Use descriptive names: `product-insights-2024-q4`
- Include date/version: `innovation-portfolio-v2`
- Follow GitHub conventions: lowercase, hyphens

### 2. Security
- Store tokens in environment variables
- Never commit tokens to version control
- Use minimal required permissions
- Rotate tokens regularly

### 3. Organization
- Create repositories in organizations for team access
- Use repository topics for categorization
- Enable issue templates for consistency

### 4. Workflow Integration
- Run after full pipeline completion
- Review generated content before creating
- Use private repos for confidential data
- Archive old repositories periodically

## Limitations

- Maximum 100 issues per batch (GitHub API limit)
- README size limited to 1MB
- Issue body limited to 65,536 characters
- Rate limits: 5,000 requests per hour for authenticated requests
